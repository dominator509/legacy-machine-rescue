# Real CNC sample smoke tests (local only)

Checked 2026-11-18. All samples were downloaded or copied to temporary FAT12 images outside the repository. No sample bytes, extracted program text, real names, or PII are committed. No G-code was executed.

This report lists 41 private sample inputs or variants across Centroid, Fanuc, Fadal, Haas, Mazak, Okuma, Siemens, HEIDENHAIN, LinuxCNC, GRBL, Mach3, TurboCNC, PlanetCNC, CAMaster, and generic G-code. This round added two official PlanetCNC demo G-code programs from the vendor's published demo profile and real install-layout checks for Estlcam and the PlanetCNC CNC USB Controller, plus a real DANCAD3D v1.30 shareware install-layout check from the archive.org preservation copy and emulated FreeDOS/QEMU execution checks of the DOS-era software (TurboCNC runs; DANCAD3D self-aborts, documented below), plus two real TurboCNC `.CNC` programs from the author's official shareware distribution plus a real TurboCNC install test, two GPLv2+ CAM-output programs from the CAMotics simulator's examples, a Centroid CNC12 ATC macro, two GPL-3.0 Fadal Renishaw probing macros from the ProbeKit project, a Siemens SINUMERIK `.MPF` example, a Fanuc-style simulator demo, a Fanuc-labelled Doosan DNM 5700 production sample, and two LinuxCNC `.ngc` examples. With the updated narrow signature, the DNM program matched by content under extensionless `O1001`; the Fanuc simulator demo still misses under extensionless `O0001`. The Siemens dialect comparison under alias `O4321` is not a Fanuc program and is expected to miss. These are file-discovery results only, not proof that a program is safe or machine-compatible.

## Method and results

The first four files were copied to a temporary FAT12 image using short aliases `LINUXCNC.NGC`, `MAZAK.NC`, `GENKEY.TAP`, and `DRILL.H`. The `.ngc`, `.nc`, and `.tap` files were detected by extension. The Heidenhain `.H` file was initially missed, then detected after a narrow signature check requiring `BEGIN PGM` plus `TOOL CALL` or `CYCL DEF` in the first 8 KiB.

The follow-up image was a separate 1.44 MB FAT12 copy containing `FANUC21.TXT`, `HAASBRK.NC`, `Z200.TAP`, and extensionless `O0007`. The Haas and Mach3 files were detected by `.NC` and `.TAP` extensions. `FANUC21.TXT` was included in the CNC-related file list due to `FANUC` in the basename, but did not produce a structured program finding. The attachment says that its Fanuc examples use an O-number filename without an extension. A 198-byte O0007 fragment extracted to a temporary extensionless file was initially missed. A narrow Fanuc signature then recognized it: an O-number header, at least three numbered G/M blocks, and an M30 or M99 end block, all within an 8 KiB prefix. This is a hint, not a parser.

A GRBL simulator `test.nc` (249 bytes, SHA-256 `9a0000e8383995d5a537c33f7928e3a1bd08ff7d83f823b1131428dbbd33b571`) was copied to a separate FAT12 image as `GRBL.NC` and detected by extension. The GRBL simulator repository declares GPL-3.0. A separate 4,841-byte Apsu `sample.gcode` (SHA-256 `ffa8a09d98621fc00ddf107003f03c46c7dad856364dd94ba564b019cf7a2b06`) is 3D-printer-style G-code, not CNC milling. Before the `.gcode` extension was added, the name appeared in the CNC-related filename list but produced no structured finding. The extension check now reports it as a possible G-code program rather than a CNC program, avoiding a false claim about additive-machine samples.

Two GPR repository samples were tested together in a private FAT12 image. `camaster_sample.tap` was detected as a possible CNC program by extension. The GPR README identifies it as Vectric output for a CAMaster router with WinCNC control. The README also identifies a Haas dialect sample, `HAAS_sample.NCF`, as taken from a machinists' forum post. Before the change, that file was not detected because `.NCF` was not in the extension list. The inventory now treats `.ncf` as a possible CNC program extension, and the same sample then matched by extension. This extension hit is only an inventory hint and may be ambiguous in other contexts. Both files stayed local and were not executed. The GPR README states the repository uses the MIT license, but the Haas sample is described as taken from a forum, and sample-specific rights for these files were not established.

A new private FAT12 image held the Fanuc, Mazak, Okuma, and Siemens samples, plus the short Heidenhain training excerpt. The Fanuc `.nc`, Mazak `.ngc`, and Siemens `.mpf` files matched by extension. The Fanuc file also matched the narrow content signature when tested under a local extensionless alias. `OPULL.SSB` was initially missed. Because its source describes it as an Okuma macro and a separate source describes `.SSB` as an Okuma subprogram format, the inventory now includes `.ssb` as a possible CNC-program extension. The 99-byte Heidenhain excerpt contains a program header and stock definition but no tool call or cycle command, so the existing narrow signature did not match it. That is an expected limit of this signature, not a syntax or compatibility verdict. All samples stayed local; nothing was run or simulated.

A separate Fanuc 0M `FANUC0M.nc` sample matched by `.NC` extension only. A Mazak-labeled `1317.EIA` file, a pair of Okuma main/subprogram text extracts named `.MIN`, and a Siemens 840D `.SPF` source-page capture were initially missed because those extensions were absent. The official HEIDENHAIN `1105_en.h` frame-point pattern sample matched the existing `.H` signature because it contains a `BEGIN PGM` header and a cycle definition. No sample was run or simulated.

The prior official HEIDENHAIN sample checks remain documented. Additional samples were privately fetched and hashed: a Siemens SINUMERIK editor example (`example.mpf`), a Fanuc-style simulator demo (`O0001_DEMO.nc`), and a Fanuc-labelled production sample for a Doosan DNM 5700 (`O1001`). The Siemens example matched by `.MPF`, but its extensionless alias `O4321` missed. The Fanuc simulator demo matched by `.NC`; alias `O0001` missed. The DNM production sample matched by `.NC`; its extensionless alias `O1001` initially missed. The DNM source attributes the program to a community contributor, so the CamCraft repository's Apache-2.0 license is not treated as permission to redistribute that sample. The Siemens repository's MIT claim is not independently verified because its linked license file returned 404. These are all local-only and unexecuted.

The Fanuc extensionless gaps observed here are specific: the synthetic simulator-demo alias `O0001` returned no content signature; the sample has only an O-number in a comment, not a standalone O-number program header. The DNM 5700 production sample's `O1001` alias is now recognized after a narrow signature adjustment: it requires a standalone O-number header, at least two numbered G/M code blocks, and an M30 or M99 end code, which may be unnumbered. The existing synthetic `O0007` signature test remains passing. The Siemens `O4321` alias is a non-Fanuc dialect comparison and is not expected to match.

Two GPL-3.0 Fadal probing macros from the ProbeKit project were copied to a private FAT12 image as `PROBEKIT.NC` and `BOREBOSS.NC`; both were detected by `.NC` extension only. `PROBEKIT.NC` was also tested under the extensionless alias `O9100` and missed: Fadal programs use no `N`-numbered blocks, so the narrow Fanuc signature, which requires at least two numbered G/M blocks, does not match them. This is a documented dialect limit, not a defect claim. The files stayed local; neither was run or simulated.

A Centroid CNC12 ATC macro from the MIT-licensed Centroid-ATC-ToolRackSetup project was copied to a private FAT12 image as `TOOLGET.CNC`. ## Emulated execution check: FreeDOS + QEMU on a real PC

After the static checks above, the DOS-era software was executed inside a QEMU virtual machine (qemu-w64 20260811, qemu-system-i386) running on a home Windows PC, installed under `F:\KiroEmu` with Dominic's approval. The boot media are patched copies of the official FreeDOS 1.3 floppy-edition boot image (`x86BOOT.img`): the language menu was removed from `FDCONFIG.SYS` and `FDAUTO.BAT` was reduced to a one-line script that starts the target program from a second FAT12 floppy holding the real distribution files. No downloaded software bytes, boot images, or screenshots are committed to this repository.

TurboCNC 4.01 (the official 2005 shareware distribution) booted and ran: its startup screen read the real `B:\TURBOCNC.INI` machine profile successfully, reported the emulated BIOS parallel ports, and calibrated against the emulated 8254 timer (2.23 microsecond mean latency) before reaching its tip-of-the-day prompt; after one keypress it displayed its full interactive control UI (menus, X/Y/Z position readout, spindle and coolant status, feed rate, jog/MDI function keys). This is real emulated execution of the actual control software, not a simulation or stub.

DANCAD3D v1.30 (the archive.org preservation copy) was attempted three times at 64 MB, 8 MB, and 4 MB of guest RAM. Each time the executable loaded and ran its startup code, then aborted with its own "Not enough memory / Program aborted" runtime message before reaching its UI. Status: executed but self-aborted; environment tuning (memory layout, DOS version expectations) remains a follow-up and is documented here honestly rather than claimed as a pass.

Caveats: these runs prove the programs start and initialize under FreeDOS in an emulator. They do not prove machine control: no parallel-port hardware, motion card, or machine was attached, and the guest had no network. Windows-era software (Mach3, Estlcam, PlanetCNC) was not executed because licensed Windows guest media is not available here; those remain static-analysis-only results.

## Caveats

These checks do not validate G-code or Klartext syntax, controller compatibility, execution, machine hardware, dongles, motion cards, DNC, or any real shop disk. The Autodesk Mazak example is incomplete and review-only, so it is not an execution test. The temporary test images contained copies only; no program was run or simulated. The extension and signature matches do not establish that any program is safe or compatible with a machine.

## Code changes

The inventory now uses bounded prefix reads only for `.H` files and filenames that are exactly an O-number with four digits. The Heidenhain signature is narrow; the Fanuc signature requires a standalone O-number header, at least two numbered G/M blocks, and an M30 or M99 end code, which can be unnumbered. This change was tested against the private DNM 5700 sample and a synthetic regression case; the Fanuc demo with only a commented O-number remains a miss. The program extension list includes `.gcode`, reported as a possible G-code program, `.ncf`, `.ssb`, `.i`, `.cnc`, and the extension-only hints `.eia`, `.min`, and `.spf`. The CNC-name hints now include `turbocnc`, `estlcam`, `cncusb`, and `dancad`, and the controller-configuration filename rule also recognizes `turbocnc`, `maxnc`, and `xylotex` brands. These matches remain inventory hints and may be ambiguous. Regression fixtures are synthetic, not third-party sample contents. No sample bytes or PII are committed. No G-code was executed.
